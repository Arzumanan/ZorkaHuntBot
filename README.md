# 🦌 Зорька — Mini App помощника охотника

`@ZorkaHuntBot` — это **Telegram Mini App**. Приложение целиком клиентское: все данные пользователя лежат в **его собственном облачном хранилище Telegram** (CloudStorage), прогноз погоды запрашивается из телефона напрямую у [Open-Meteo](https://open-meteo.com/). Бот остаётся минимальным: `/start` и кнопка запуска. **Ни сервер, ни ПК автора личных данных не хранят.**

## Как это работает для пользователя

* Бот отвечает на `/start`: короткое приветствие и кнопка **«🌄 Открыть Зорьку»**. Та же кнопка стоит в меню чата рядом с полем ввода. На любое другое сообщение бот отвечает только кнопкой запуска.
* Утренней рассылки больше нет: бот ничего не присылает сам.
* Весь функционал в приложении, пять разделов внизу экрана:

| Раздел | Что внутри |
|---|---|
| 🌦 **Прогноз** | переключатель «Погода» / «Активность», выбор угодья. **Погода:** «Сегодня, 20 ноября» и «Завтра, 21 ноября», оценка дня 1–5, восход, закат, луна, утренняя и вечерняя зорька, графики ветра, давления, температуры и осадков. **Активность:** обе даты сразу, утро и вечер 1–5 для водоплавающей, боровой дичи, копытных, **фазана** и **зайца**, с причинами оценки |
| 🗺 **Карта** | охотничий навигатор: схема / спутник / рельеф, ваша позиция, метки (вышка, солонец, лабаз, место подъёма, машина, другое), «вернуться к метке» с расстоянием и азимутом, стрелка сноса запаха, ваши угодья с переходом в прогноз. Уже на карте: два участка ОДОУ Майкопского района (указ Адыгеи №114), 27 зон «охота запрещена» в Тахтамукайском районе (указ №158), общедоступные угодья 16 районов Краснодарского края — 40 участков и 8 закреплённых угодий Северского района (постановление №464, сверка площади) и ООПТ Адыгеи и Краснодарского края (OpenStreetMap, ODbL); границы ориентировочные |
| 📅 **Сезоны** | сроки охоты по региону: открыто / скоро / закрыто, по категориям, с источниками. Краснодарский край и Республика Адыгея стоят первыми |
| 🎒 **Чек-лист** | вид охоты (водоплавающая, боровая, копытные, общий), категории «Оружие и патроны», «Документы», «Снаряжение», «Еда и питьё»; отметки сохраняются отдельно для каждого вида охоты, свои пункты, «Сбросить отметки», подсказки по погоде для основного угодья |
| 📖 **Журнал** | записи (дата, угодье, дичь, заметка), добавление и удаление; статистика показывается, только если записи есть |
| ⚙️ **Ещё** | угодья (по городу или координатам, переименовать, удалить, сделать основным), регион, текущее место, часовой пояс, блок «🔒 О данных» с кнопкой «Удалить все данные» |

### Про активность зверя и птицы

Это ориентировочная оценка по правилам, а не гарантия (приложение каждый раз это пишет). Для фазана и зайца заложены свои правила:

* **Фазан:** кормится утром и вечером у кромок и укрытий, не любит дождь и снег, ветер выше 6 м/с и сильный мороз; луна на него не влияет.
* **Заяц:** активнее в сумерки и ночью (вечер сильнее утра), любит тихую погоду, сильный ветер и ливень заставляют лежать; свежий снег ночью («пороша») повышает оценку; яркая луна снижает утреннюю активность.

## Архитектура

```
Telegram-клиент ── открывает ──► webapp/ (статика: GitHub Pages или ваш сервер/туннель)
      │                              │
      │  CloudStorage (ваши данные)  │  JS-логика: оценка дня, активность, луна, сезоны, статистика
      ◄──────────────────────────────┤
                                     └─► api.open-meteo.com / geocoding-api.open-meteo.com (только координаты и название города)

бот (python -m bot.main): /start + кнопка WebApp + кнопка меню; опционально раздаёт webapp/
```

* **Хранилище.** `Telegram.WebApp.CloudStorage` привязано к пользователю и боту (не к адресу сайта), поэтому данные одинаковы на всех устройствах и при переезде с туннеля на GitHub Pages. Лимиты Telegram: 1024 ключа, ключ до 128 символов `[A-Za-z0-9_-]`, значение до 4096 символов. Приложение их соблюдает:
  * ключи: `meta` (регион, часовой пояс, вид охоты, текущее место), `places`, `marks` (метки на карте), `ck_<вид охоты>` (отметки и свои пункты), `j_<ГГГГММДД>_<id>` (одна запись журнала на ключ), `mig` (метка переноса, не личные данные);
  * большое значение режется на части `<ключ>__c1…__cN` по ≤3500 байт, в основном ключе лежит заголовок `{"__chunks":N}`; сначала пишутся части, потом заголовок, потом удаляются лишние старые части;
  * пользовательские пределы: угодий до 30, меток на карте до 200, своих пунктов чек-листа до 100 на вид охоты, записей журнала до 900; при превышении или при заполненном хранилище приложение показывает понятное сообщение, а не теряет данные молча.
* **Запасной вариант.** Если CloudStorage недоступно (клиент Telegram старше 6.9 или обычный браузер), данные лежат в `localStorage` этого браузера с теми же лимитами. Для пользователей Telegram это не основной режим, а для разработки удобно.
* **Погода.** Приложение само вызывает Open-Meteo (прогноз и геокодер). Ответ прогноза кэшируется в памяти на 10 минут.
* **Что считает JS.** Всё, что раньше считал Python: разбор прогноза (тренд давления, свежий снег до рассвета и заката), оценка дня 1–5, активность для всех групп, фаза луны, расчёт сроков охоты, подсказки чек-листа, статистика. Результаты проверяются на соответствие прежней реализации (`tests/js/fixtures/golden.json`, снят со старого Python-кода).
* **Статические данные:** `webapp/data/seasons.json`, `regions.json`, `checklist.json`.
* **Часовой пояс** («Ещё → Часовой пояс», по умолчанию «как на устройстве») нужен для «сегодня» в журнале и сроках. Прогноз считается по поясу самого места.

## 🔒 О данных (то же показывает приложение в «Ещё»)

* Всё, что вы вводите, хранится в облачном хранилище вашего Telegram и на вашем устройстве. Сервер автора ничего не хранит.
* Чтобы показать вас на карте, приложение запрашивает геопозицию через Telegram или браузер; она остаётся на устройстве и в фоне не пишется (когда вкладка закрыта, слежения нет).
* Для прогноза и стрелки ветра координаты выбранного места (и название города при поиске) уходят напрямую в Open-Meteo (за пределами РФ). Больше никому.
* Карта рисуется библиотекой [Leaflet](https://leafletjs.com/) (лицензия BSD-2-Clause, лежит в `webapp/vendor/leaflet/`). Подложки: OpenStreetMap, снимки Esri и OpenTopoMap; их серверы видят ваш IP, как любой сайт.
* Данные при этом обрабатывает сам Telegram как часть своего облака; это нужно учитывать, если вам важно, где они лежат.
* Кнопка **«Удалить все данные»** стирает все ключи хранилища (и просит ПК стереть старую копию, если она осталась).
* Экрана согласия и страницы политики больше нет: у автора нет персональных данных, которые нужно собирать.
* ⚠️ Это описание, а не юридическая консультация.


## Карта (навигатор)

Вкладка «Карта» целиком клиентская, как и остальное приложение.

* **Подложки.** Схема (OpenStreetMap), спутник (Esri World Imagery), рельеф (OpenTopoMap). Leaflet подгружается только при первом открытии вкладки, из `webapp/vendor/leaflet/`, без CDN.
* **Я на карте.** Сначала пробуем `Telegram.WebApp.LocationManager` (клиент Telegram 8.0+), иначе `navigator.geolocation`. Точка и круг точности обновляются, пока вкладка открыта (примерно раз в 8 секунд). Если доступ запрещён, есть кнопка «Открыть настройки». В свёрнутом приложении и на других вкладках геопозиция не запрашивается.
* **Метки.** Типы: вышка, солонец, лабаз, место подъёма, машина, другое. Добавить — долгим нажатием на карте или кнопкой «Метка здесь». Имя и заметка необязательны. Хранятся в ключе `marks` (координаты с точностью до 6 знаков). Предел — 200 меток.
* **«Вернуться к…».** По умолчанию выбирается первая метка «Машина». Показывается расстояние и азимут; если доступен компас устройства (`DeviceOrientation` в Telegram или в браузере, на iOS нужно разрешение), стрелка ориентируется относительно вашего курса, иначе — относительно севера, и на карте рисуется линия до цели.
* **Ветер и запах.** Для вашей позиции (или центра карты) берётся текущий час из Open-Meteo. Метеорологическое направление — *откуда* дует ветер; стрелка показывает, *куда* сносит запах (направление + 180°). Если выбрана метка, есть подсказка: заходить с подветренной стороны.
* **Угодья.** Сохранённые угодья — точки на карте, из подписи можно открыть прогноз или активность.
* **Границы угодий.** В `webapp/data/boundaries/index.json` — список файлов (можно указывать `region`, `district`, `type` и добавлять районы по одному). Сейчас на карте: ОДОУ Майкопского района, участки №1 и №3 (указ Главы РА №114 от 31.08.2026); 27 зон, где охота запрещена, в Тахтамукайском районе (указ Главы РА №158 от 19.12.2023, приложение №10); общедоступные угодья 16 районов Краснодарского края (40 участков, включая город Краснодар и Красноармейский район) и 8 закреплённых угодий Северского района с указанием охотпользователя, все прошедшие сверку площади с постановлением губернатора №464 от 20.07.2026 (остальные районы края пока на паузе); ООПТ Адыгеи (7) и Краснодарского края (71) по данным OpenStreetMap (ODbL). Слой включается в меню подложки, с оговоркой: «Границы ориентировочные, по официальным схемам; не проверены — сверяйтесь с охотпользователем». Когда включены ООПТ, в источниках карты появляется «OSM contributors (ODbL)».

Ограничения первой версии: нет записи трека, нет работы без интернета (тайлы и ветер нужны с сети), нет фонового слежения за геопозицией.

## ⚠️ Про сроки охоты

Сроки охоты — справочная информация, а не юридический документ. Точные сроки уточняйте в региональном охотуправлении / указе главы региона. Приложение показывает эту оговорку на странице «Сезоны».

Данные лежат в `webapp/data/seasons.json`:

* `federal` — федеральные рамки по приказу Минприроды № 477 от 24.07.2020 (в ред. от 25.12.2025). Применяются к любому региону без собственных записей.
* `regions.<код>` — записи региона. Запись с тем же `id`, что и в `federal`, заменяет федеральную.
* у каждой записи есть `confidence` (`federal`, `regional_official` — текст акта региона прочитан, `regional_reported` — по региональным СМИ, нужно проверить) и ссылка на источник из раздела `sources`.

Регионы с собственными данными: Краснодарский край, Республика Адыгея, Московская область, Тверская область. Остальные работают по федеральным рамкам, и приложение прямо об этом говорит.

Формат дат: `"10-15"` — 15 октября; `"sat3-08"` — третья суббота августа; `"eom-02"` — последний день февраля; если конец раньше начала, сезон переходит на следующий год; вместо `end` можно указать `"days": 10`. Чтобы добавить регион, допишите блок в `regions` (код берите из `webapp/data/regions.json`) и поставьте `"verified": true`, если источники проверены. Тест `tests/js/seasons.test.js` проверит целостность данных.

## Запуск на Windows (Python 3.11+)

В PowerShell или cmd, в папке проекта (`E:\ZorkaHuntBot`):

```powershell
cd E:\ZorkaHuntBot
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env      # если файла .env ещё нет; впишите BOT_TOKEN=...
python -m bot.main
```

Если в папке уже лежит готовый `.env` с токеном, команду `copy` пропустите. Если PowerShell не даёт активировать venv: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. Остановить: `Ctrl+C`.

> ⚠️ Бот работает через long polling: одновременно запускайте только **один** экземпляр с этим токеном, иначе будет ошибка `Conflict: terminated by other getUpdates request`.

Приложение запускается только **inline-кнопкой** (под сообщением) или **кнопкой меню чата**: кнопки обычной клавиатуры данные Mini App не передают. Бот сам ставит кнопку меню при запуске (в BotFather ничего настраивать не нужно). В меню команд одна команда: `/start`.

### Переменные `.env`

| Ключ | Что это | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен бота из @BotFather | обязателен |
| `WEBAPP_URL` | публичный https-адрес приложения (туннель или GitHub Pages) | не задан (кнопки запуска нет) |
| `WEBAPP_HOST`, `WEBAPP_PORT` | где слушает локальный веб-сервер бота | `127.0.0.1`, `8080` |
| `DB_PATH` | **временно:** путь к старой базе для переноса | `zorka.db` |
| `WEBAPP_CORS_ORIGIN` | **временно:** Origin страницы Pages, только для переноса | не задан |

Убраны: `POLICY_OPERATOR`, `POLICY_CONTACT`, `WEBAPP_DEV_USER_ID` (политики и режима разработки с чужим пользователем больше нет). Лишние строки в вашем `.env` бот просто игнорирует.

### Вариант 1. Туннель cloudflared (быстро, на своём ПК)

Telegram открывает Mini App только по https:

1. `winget install --id Cloudflare.cloudflared`.
2. Запустите бота: `python -m bot.main` (веб-сервер на `http://127.0.0.1:8080` раздаёт `webapp/`).
3. Во втором окне: `cloudflared tunnel --url http://127.0.0.1:8080`. Найдите адрес вида `https://что-то-там.trycloudflare.com`.
4. Впишите его в `.env`: `WEBAPP_URL=...`, перезапустите бота, напишите ему `/start`.

Адрес «быстрого» туннеля меняется при каждом запуске, поэтому шаги 4–5 придётся повторять. Данные при этом не теряются: они в вашем Telegram, а не на адресе.

### Вариант 2. GitHub Pages (постоянный адрес, ПК не нужен)

Раз приложению не нужен ни сервер, ни API, его можно целиком выложить как статику:

1. В репозитории: **Settings → Pages → Source: GitHub Actions** (включается вручную один раз).
2. Workflow `.github/workflows/pages.yml` при каждом пуше в `main` прогоняет `node --test` и публикует папку `webapp/`.
3. В `.env`: `WEBAPP_URL=https://arzumanan.github.io/ZorkaHuntBot/`, перезапустите бота (боту нужен только ради `/start`, а раздавать статику ему больше не требуется).

Все пути в `webapp/` относительные, поэтому приложение работает в подкаталоге `/ZorkaHuntBot/`. Для обновления клиентов с кэшем поднимайте `?v=` в `webapp/index.html` (один номер на все файлы; тест `static.test.js` проверяет, что он везде одинаковый).

### Проверка без Telegram

Откройте `http://127.0.0.1:8080/` (бот запущен) или любой статический сервер в папке `webapp/` (`python -m http.server 8000 -d webapp`). Данные тогда лежат в `localStorage`. Адрес `/?tab=checklist` открывает нужный раздел (`weather`, `seasons`, `checklist`, `journal`, `more`). Оговорка: `ready()`, тема и виброотклик Telegram в браузере не работают.

## ⏳ ВРЕМЕННО: перенос данных из старой версии

Раньше данные лежали в `zorka.db` на ПК автора. Чтобы владельцы старых данных ничего не потеряли, есть разовый перенос. **После того как все нужные пользователи открыли новую версию, его надо удалить** (список ниже).

Как работает:

1. При первом запуске **внутри Telegram** с пустым `mig` приложение делает `GET /api/legacy-export` (заголовок `X-Telegram-Init-Data`, сервер проверяет подпись HMAC по токену бота и отдаёт данные только этого пользователя). Если файла `zorka.db` нет или данных пользователя нет, сервер отвечает `404` JSON `{"error":"no_legacy_db"|"no_legacy_data"}`, и приложение ставит `mig=skipped`.
2. Если данные есть, приложение **сливает** их в CloudStorage (угодья, журнал, регион/пояс/вид охоты/место, отметки и свои пункты чек-листа; повтор безопасен, дубликатов нет, уже настроенное в новом приложении не затирается), ставит `mig=imported` и вызывает `POST /api/legacy-export/done`. Сервер удаляет строки этого пользователя из всех таблиц и делает `VACUUM`. После успеха `mig=done`.
3. Если сервер недоступен, приложение не ставит метку и повторит попытку при следующем запуске (при ошибке `done` повторяется только `done`). Страница Pages, у которой нет `/api`, отвечает HTML-404: он **не** считается «данных нет».
4. «Удалить все данные» оставляет только `mig` (это не личные данные), чтобы старая база не воскресила удалённое, и ещё просит сервер стереть старые строки.

Условия: старый сервер должен быть доступен по https в момент первого запуска. Если приложение раздаёт сам бот (туннель), больше ничего не нужно. Если приложение открывается с Pages, а старая база осталась на ПК: поднимите бота с туннелем, в `.env` задайте `WEBAPP_CORS_ORIGIN=https://arzumanan.github.io`, а в `webapp/index.html` в блоке `window.ZORKA_API_BASE` впишите адрес туннеля (временно). Данные в CloudStorage привязаны к пользователю и боту, так что импорт через любой адрес виден и на всех остальных.

**Что удалить после переноса:** `bot/legacy.py`, маршруты `/api/legacy-export*` и CORS в `bot/web/server.py`, `bot/web/auth.py`, `db_path`/`webapp_cors_origin` в `bot/config.py` и `.env`, `webapp/lib/migrate.js` (и подключение в `index.html`), вызовы `migrateLegacy`/`cleanupServer` в `webapp/app.js` и `webapp/more.js`, блок `ZORKA_API_BASE` в `index.html`, тесты `tests/test_legacy.py`, `tests/test_web_auth.py`, `tests/js/migrate.test.js`, и сам файл `zorka.db` (после этого удалите его с ПК и из резервных копий).

## Тесты

```powershell
venv\Scripts\activate
pytest          # бот, веб-сервер, перенос (без сети)
node --test     # JS-логика и хранилище (нужен Node.js 20+, без npm-пакетов)
```

`node --test` без аргументов сам находит `tests/js/*.test.js` (с путём к папке на новых Node не работает). Что проверяется:

* `golden.test.js`: оценка дня, активность, луна, прогноз со снегом, сезоны, чек-лист, статистика совпадают с эталонами, снятыми со старого Python-кода;
* `seasons.test.js`, `rules.test.js`: правила дат, границы статусов (30 дней «скоро»), целостность данных, граничные случаи;
* `storage.test.js`: нарезка больших значений (поддельный CloudStorage с лимитами Telegram), очистка лишних частей, лимиты 4096/1024, сообщения об ошибках, выбор хранилища по версии клиента, localStorage;
* `data.test.js`: угодья, чек-лист, журнал, настройки, прогноз и кэш, ошибки погоды, удаление всех данных;
* `migrate.test.js`: перенос старых данных (слияние, повтор, сбои сети);
* `nav.test.js`: расстояние, азимут, компас, снос запаха, проверка меток;
* `static.test.js`: пути, версии `?v=`, отсутствие `innerHTML`, лишних адресов, остатков согласия и рассылки, вкладка «Карта» и вендор Leaflet.

## Безопасность токена

Файл `.env` в `.gitignore` и не должен попадать в репозиторий. Если токен где-то засветился, перевыпустите его в `@BotFather` (`/revoke`) и обновите `.env`. Токен нужен только боту и разовому переносу; в `webapp/` его нет.

Ввод собственных дат сезона, больше проверенных регионов, карта угодий, фото к записям журнала, редактирование записей журнала, экспорт и импорт данных файлом.
