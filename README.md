# 🦌 Зорька — Mini App помощника охотника

`@ZorkaHuntBot` — это **Telegram Mini App**: всё работает внутри приложения, а сам бот остаётся минимальным.

## Как это работает для пользователя

* Бот отвечает на `/start`: короткое приветствие (старая клавиатура с кнопками убирается) и кнопка **«🌄 Открыть Зорьку»**. Та же кнопка стоит в меню чата рядом с полем ввода. На любое другое сообщение или старую команду бот отвечает только кнопкой запуска.
* Утренняя рассылка (суббота и воскресенье, только если в регионе открыт сезон) приходит сообщением с той же кнопкой.
* Весь функционал в приложении, пять разделов внизу экрана:

| Раздел | Что внутри |
|---|---|
| 🌦 **Прогноз** | переключатель «Погода» / «Активность», выбор угодья. **Погода:** «Сегодня, 20 ноября» и «Завтра, 21 ноября», оценка дня 1–5, восход, закат, луна, утренняя и вечерняя зорька, графики ветра, давления, температуры и осадков. **Активность:** обе даты сразу, утро и вечер 1–5 для водоплавающей, боровой дичи, копытных, **фазана** и **зайца**, с причинами оценки |
| 📅 **Сезоны** | сроки охоты по региону: открыто / скоро / закрыто, по категориям, с источниками. **Краснодарский край и Республика Адыгея стоят первыми** в списке регионов |
| 🎒 **Чек-лист** | вид охоты (водоплавающая, боровая, копытные, общий), категории «Оружие и патроны», «Документы», «Снаряжение», «Еда и питьё»; отметки сохраняются в базе отдельно для каждого вида охоты, свои пункты (добавить и удалить), «Сбросить отметки», счётчик, подсказки по погоде для основного угодья, виброотклик Telegram |
| 📖 **Журнал** | записи (дата, угодье, дичь, заметка), добавление и удаление; статистика (выезды, трофеи, по дичи, угодьям, месяцам, лучшие месяцы) показывается, только если записи есть |
| ⚙️ **Ещё** | угодья (добавить по городу или координатам, переименовать, удалить, сделать основным), регион, текущее место, утренняя рассылка (вкл/выкл, время, часовой пояс) |

Погода — [Open-Meteo](https://open-meteo.com/) (ключ не нужен). Фаза луны считается локально. Данные хранятся в SQLite (`zorka.db`).

### Про активность зверя и птицы

Это ориентировочная оценка по правилам, а не гарантия (бот и приложение каждый раз это пишут). Для фазана и зайца заложены свои правила:

* **Фазан:** кормится утром и вечером у кромок и укрытий, не любит дождь и снег, ветер выше 6 м/с и сильный мороз; луна на него не влияет.
* **Заяц:** активнее в сумерки и ночью (вечер сильнее утра, днём лежит), любит тихую погоду, сильный ветер и ливень заставляют лежать; свежий снег ночью («пороша») повышает оценку, потому что заяц ходит, а следы читаются; яркая луна снижает утреннюю активность.

## ⚠️ Про сроки охоты

Сроки охоты — справочная информация, а не юридический документ. Точные сроки уточняйте в региональном охотуправлении / указе губернатора.

Данные лежат в `bot/data/seasons.json`:

* `federal` — федеральные рамки по приказу Минприроды № 477 от 24.07.2020 (в ред. от 25.12.2025). Они применяются к любому региону без собственных записей.
* `regions.<код>` — записи региона. Запись с тем же `id`, что и в `federal`, заменяет федеральную.
* у каждой записи есть `confidence` (`federal`, `regional_official` — текст акта региона прочитан, `regional_reported` — по региональным СМИ и справочным сайтам, нужно проверить) и ссылка на источник из раздела `sources`.

Регионы с собственными данными сейчас: Краснодарский край, Республика Адыгея, Московская область, Тверская область (степень проверки и источники приложение показывает во вкладке «Сезоны»). Остальные регионы работают по федеральным рамкам, и приложение прямо об этом говорит.

Формат дат: `"10-15"` — 15 октября; `"sat3-08"` — третья суббота августа; `"eom-02"` — последний день февраля; если конец раньше начала, сезон переходит на следующий год; вместо `end` можно указать `"days": 10`.
Чтобы добавить регион, допишите блок в `regions` (код региона берите из `bot/data/regions.json`) и поставьте `"verified": true`, если источники проверены. Тест `tests/test_seasons.py` проверит целостность данных.

## Запуск на Windows (Python 3.11+)

В PowerShell или cmd, в папке проекта (`E:\ZorkaHuntBot`):

```powershell
cd E:\ZorkaHuntBot
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env      # если файла .env ещё нет; впишите BOT_TOKEN=...
python -m bot.main
```

Если в папке уже лежит готовый `.env` с токеном, команду `copy` пропустите.
Если PowerShell не даёт активировать venv, выполните один раз:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

Остановить: `Ctrl+C`.

> ⚠️ Бот работает через long polling: одновременно запускайте только **один** экземпляр с этим токеном, иначе будет ошибка `Conflict: terminated by other getUpdates request`.

## Запуск и подключение Mini App

Веб-сервер (aiohttp) работает **в том же процессе, что и бот**: отдаёт статику из `webapp/` и JSON API `/api/...`. Каждый запрос подписан Telegram (`initData`): сервер проверяет HMAC-SHA256 по токену бота и возраст подписи (до 24 часов). Без валидной подписи API отвечает 401, данные каждого пользователя изолированы.

> Запускать приложение можно только **inline-кнопкой** (под сообщением) или **кнопкой меню чата**: кнопки обычной (reply) клавиатуры подписанную `initData` не передают. Бот сам ставит кнопку меню при запуске (через BotFather ничего настраивать не нужно). В меню команд бота осталась одна команда: `/start`.

### Переменные `.env`

| Ключ | Что это | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен бота из @BotFather | обязателен |
| `DB_PATH` | путь к файлу SQLite | `zorka.db` |
| `WEBAPP_URL` | публичный **https**-адрес Mini App. Пусто: бот только сообщает, что приложение не настроено | пусто |
| `WEBAPP_HOST` | на каком адресе слушает веб-сервер | `127.0.0.1` |
| `WEBAPP_PORT` | порт веб-сервера | `8080` |
| `WEBAPP_DEV_USER_ID` | **только для разработки**: запросы без `initData` считаются запросами этого Telegram ID (чтобы открыть приложение в обычном браузере). В боевой работе оставляйте пустым | пусто |
| `WEBAPP_CORS_ORIGIN` | разрешённый Origin, если статика лежит на другом домене (например, GitHub Pages) | пусто |
| `POLICY_OPERATOR` | кто указан оператором данных в политике конфиденциальности (ваше имя / ИП) | `автор бота @ZorkaHuntBot` |
| `POLICY_CONTACT` | контакт для вопросов и отзыва согласия (e-mail, ссылка на Telegram) | через бота |

### Конфиденциальность и согласие

- **Что хранится:** Telegram ID, регион и часовой пояс, координаты и названия угодий, записи журнала, отметки чек-листа, настройки рассылки, а также версия принятой политики и время принятия. Имя и username из Telegram **не сохраняются**, сообщения пользователей тоже.
- **Экран согласия.** При первом открытии (и после смены версии политики) приложение показывает краткую сводку, ссылку на полный текст, галочку и кнопку «Принимаю». Пока согласия нет, API всех методов, которые читают или пишут личные данные, отвечает `403 {"error": "consent_required"}`. Без согласия работают только `GET /api/policy`, `GET /privacy` (полный текст, публично), `GET /api/regions`, `GET /api/me` (отдаёт лишь статус согласия), `POST /api/consent` и `POST /api/account/delete`. Утренняя рассылка пользователям без согласия текущей версии не отправляется. Это в том числе означает, что после обновления версии политики рассылка у каждого возобновится только после того, как он откроет приложение и примет её.
- **Удаление данных.** «Ещё → Удалить мои данные» (с подтверждением) вызывает `POST /api/account/delete` и стирает все строки пользователя во всех таблицах, включая согласие и подписку. Дальше приложение снова спросит согласие.
- **Оператор.** Текст политики лежит в `bot/policy.py`. Впишите своё имя и контакт через `POLICY_OPERATOR` / `POLICY_CONTACT` в `.env` (или в `DEFAULT_OPERATOR` / `DEFAULT_CONTACT` в `bot/policy.py`: там помечено «ЗАПОЛНИТЕ»).
- **Новая редакция политики.** Если вы меняете текст по существу, поменяйте `POLICY_VERSION` в `bot/policy.py`: все пользователи увидят экран согласия снова, их данные при этом не удаляются.
- **Режим разработки** (`WEBAPP_DEV_USER_ID`) тоже требует согласия: примите его на экране при первом открытии.
- ⚠️ Текст политики написан без юриста и не является юридической консультацией; о регистрации в Роскомнадзоре в нём ничего не заявляется. Пункт «данные хранятся на сервере в РФ» верен, только пока бот запущен в России (например, на вашем ПК); при переезде на зарубежный VPS поправьте текст политики и поднимите `POLICY_VERSION`. Сводка также упоминает, что трафик через туннель Cloudflare проходит через их серверы, и что погодные запросы уходят в Open-Meteo (за пределами РФ).

### Запуск с туннелем cloudflared (быстрый способ на своём ПК)

Telegram открывает Mini App только по https, а бот стоит у вас на компьютере. Бесплатный временный туннель Cloudflare решает это без регистрации:

1. Установите cloudflared: `winget install --id Cloudflare.cloudflared`.
2. Запустите бота: `python -m bot.main` (веб-сервер поднимется на `http://127.0.0.1:8080`).
3. Во **втором** окне PowerShell: `cloudflared tunnel --url http://127.0.0.1:8080`. В выводе найдите адрес вида `https://что-то-там.trycloudflare.com`.
4. Впишите его в `.env`: `WEBAPP_URL=https://что-то-там.trycloudflare.com`.
5. Перезапустите бота (Ctrl+C и снова `python -m bot.main`). Напишите боту `/start` и нажмите «Открыть Зорьку» (или кнопку меню рядом с полем ввода).

У «быстрого» туннеля адрес **меняется при каждом запуске** cloudflared, и тогда нужно повторить шаги 4 и 5. Пока компьютер выключен или туннель не запущен, приложение не откроется.

### Проверка без Telegram (режим разработки)

В `.env` поставьте `WEBAPP_DEV_USER_ID=<ваш Telegram ID>`, запустите бота и откройте `http://127.0.0.1:8080/` в браузере: API будет считать вас этим пользователем. Telegram-специфичные вещи (`ready()`, тема, виброотклик) в браузере не работают, но все разделы работают. Адрес вида `http://127.0.0.1:8080/?tab=checklist` открывает нужный раздел сразу (`weather`, `seasons`, `checklist`, `journal`, `more`). **Не включайте это на публичном адресе:** любой, кто знает адрес, получит доступ к данным этого пользователя.

### Постоянный хостинг

- **VPS** (любой Linux с Python 3.11+): запустить бота как systemd-сервис, поставить перед ним Caddy или nginx с сертификатом Let's Encrypt и проксировать домен на `127.0.0.1:8080`. `WEBAPP_URL=https://ваш-домен`. Это самый простой постоянный вариант: один процесс, ничего больше не нужно.
- **Статика на GitHub Pages, API отдельно**: папку `webapp/` можно выложить на Pages, но API всё равно должен быть на https-хосте с ботом. Тогда в `.env` бота задайте `WEBAPP_CORS_ORIGIN=https://<логин>.github.io`, а в `webapp/index.html` перед `core.js` уже есть строка `window.ZORKA_API_BASE`, впишите в неё адрес API, например `"https://адрес-вашего-api"`. `WEBAPP_URL` указывает на страницу Pages.

### API (для справки)

Все маршруты `/api/*`, кроме `GET /api/policy`, требуют заголовок `X-Telegram-Init-Data`. Новое: `GET /api/policy` (публично), `GET /privacy` (HTML-страница политики, публично), `POST /api/consent` (`{accept: true, version}`), `POST /api/account/delete`. Всё остальное, кроме `/me` и `/regions`, требует принятого согласия (иначе 403 `consent_required`). Чтение: `GET /api/me`, `/forecast?place_id=`, `/activity?place_id=`, `/seasons`, `/regions`, `/checklist`, `/places`, `/journal`, `/stats`, `/settings`. Изменения (все `POST`, JSON): `/region`, `/location`, `/checklist/{type,toggle,add,delete,reset}`, `/places`, `/places/{update,delete}`, `/journal`, `/journal/delete`, `/settings`.

## Тесты

```powershell
venv\Scripts\activate
pytest
```

Тесты не ходят в сеть: ответы Open-Meteo подменены тестовым JSON (`tests/conftest.py`), бот проверяется через поддельную сессию Telegram, API через `aiohttp.test_utils` с временной БД.

## Структура

```
bot/
  main.py            точка входа: бот (только /start), веб-сервер, планировщик
  config.py          токен, путь к БД и настройки Mini App из .env
  db.py              SQLite: места, журнал, настройки, угодья, чек-лист, согласия
  policy.py          текст политики конфиденциальности, версия, оператор
  keyboards.py       кнопка запуска Mini App (inline) и подписи старой клавиатуры
  utils.py           разбор дат
  data/              seasons.json (сроки охоты), regions.json (список регионов)
  handlers/common.py /start, ответ на любой другой текст
  web/
    auth.py          проверка initData (чистые функции)
    helpers.py       общие помощники обработчиков
    payloads.py      сборка JSON прогноза и активности
    api.py           aiohttp: статика, middleware, /me, /forecast, /activity, /seasons, /regions, /region, /location
    routes_user.py   чек-лист, угодья, журнал, статистика, настройки
  services/
    weather.py       запросы и разбор ответов Open-Meteo (в том числе свежий снег для «пороши»)
    moon.py          фаза луны
    scoring.py       оценка дня 1–5
    activity.py      активность 1–5: водоплавающая, боровая, копытные, фазан, заяц
    seasons.py       расчёт сроков охоты по данным seasons.json
    subscription.py  «слать ли сегодня», «пора ли сейчас», часовые пояса
    scheduler.py     asyncio-планировщик утренней рассылки (с кнопкой Mini App)
    checklist.py     шаблоны чек-листа и подсказки по погоде
    stats.py         статистика журнала
    locations.py     выбор угодья для прогноза
    forecast_text.py текст утренней рассылки
webapp/              Mini App без сборки и CDN (только telegram-web-app.js с telegram.org):
                     index.html, style.css, core.js, weather.js, seasons.js, checklist.js, journal.js, more.js, app.js
tests/               pytest: сервисы, БД, бот, планировщик, auth и API
```

## Безопасность токена

Файл `.env` в `.gitignore` и не должен попадать в репозиторий. Если токен где-то засветился, перевыпустите его в `@BotFather` (`/revoke`) и обновите `.env`.
